The Tax rules API has seven endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/tax_rules`.

<Warning>
  **`code`, `zones`, `decimal_point` and `rounding_type` cannot be set through this API.** Create and
  update accept them and return success, but store none of them. A rule you create has `code: {}`,
  `zones: []`, `decimal_point` set to `2` and `rounding_type` set to `nearest`, whatever you send, and
  an update leaves these four fields as they were.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Wrap every write in `tax_rule`.** Send `{"tax_rule": {"name": "Reduced rate"}}` to create or
  update a rule. A bare record is rejected with `400` and the message `tax_rule missing`. On create,
  `name` is required and a body without it fails with `500`; `description` is the only other field
  the store reads. An update changes only the fields you send.
- **A listing returns at most 20 rules per call.** A larger `limit` is capped at `20`, and
  `pagination.limit` shows `20`. To read every rule, step `offset` by the number of rules each page
  returned until you reach `pagination.total`. A `limit` below `1`, or a `limit` or `offset` that is
  not a number, is rejected with `400` and the error `invalid_pagination`.
- **A rejected request can make the next request on the same connection fail too.** Straight after a
  `404`, the next retrieve returns `404`, even for a tax rule that exists. A retrieve from another tax
  collection returns `404` with that collection's own message, such as `Profile not found`. Straight
  after a `400` `invalid_pagination`, the next listing returns the same `400`, even on another tax
  collection. The request after that is handled normally. So a delete sent straight after a `404`
  returns that `404` and deletes nothing. Check the status of every call, and send the delete again
  when it returns the previous call's error.
- **A `200` does not always mean the call worked.** A method these paths do not handle, such as
  `OPTIONS`, returns `200` with `{"isSuccess": false, "message": "Invalid API Request"}` instead
  of `405`, and stores nothing. A `HEAD` request for one rule returns `200` even when no rule has the
  `tax_rule_id` you send; use [Retrieve a tax rule](/api-reference/tax-rules/retrieve-a-tax-rule) to check that a rule exists.
- **Tax rules live at `/admin/tax_rules`, not under `/admin/tax/`.** `/admin/tax/custom_rules`, the
  path an older API collection used, returns `404` with the error code `not_found` and a message that
  starts `Unknown tax path`.
