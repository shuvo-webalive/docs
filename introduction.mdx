WebCommander exposes a store's admin data through the **v4 REST API**: customers, page and store
settings, tax, shipping, inventory locations, order flags and domain aliases. Seven SDKs wrap that
API with the same surface in every language, so a call you learn in one reads the same in the
others.

| Language | Package |
| --- | --- |
| Python | `webcommander-sdk` (import `webcommander`) |
| JavaScript | `webcommander-sdk` |
| PHP | `webcommander/sdk` |
| Java | `com.webcommander:webcommander-sdk` |
| .NET | `WebCommander.Sdk` |
| Dart | `webcommander_sdk` |
| Go | `bitbucket.org/webalive/webcommander-sdk-go/v3` |

All seven are at version 3.5.0.

## What the API covers

These docs describe only the endpoints that all seven SDKs implement. If a call is documented here,
you can make it from any of the seven languages.

| Area | What you can do |
| --- | --- |
| Customers | List, read, create, update and delete customers, export and import them, manage addresses, passwords and store credit |
| Page settings | Read and update the category, product, search result, shopping cart and checkout page settings |
| Store settings | Read and update site, e-commerce, customer portal, price display, product listing, search, SEO, shipping and animation settings |
| Tax | Manage tax codes, rules, zones, profiles, custom profiles, country taxes and the store's tax settings |
| Shipping | Manage shipping methods and shipping classes |
| Inventory and orders | Manage inventory locations and order flags |
| Domain aliases | List, add and remove the extra hostnames a store answers on |

## What every SDK does for you

- **Authentication.** You give the client your store's credentials. It exchanges them for an access
  token, caches the token and renews it when it expires.
- **One client, every resource.** Each area above is a property on the client, and each endpoint is
  a method on that property.
- **Responses as sent.** You get the body exactly as the API returned it, with an optional typed
  view over the top.
- **Real failures.** A non-2xx status is a failure. So is a `200` whose body says
  `"isSuccess": false`, which the API returns for a path it cannot route.
- **Retries and timeouts.** Calls that certainly did not reach the store are retried with backoff.
