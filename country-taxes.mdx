The Country taxes API has five endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/tax/country-taxes`, with a hyphen. The old path `/api/v4/admin/tax/country_taxes`, with an underscore, returns `404` with the message `Unknown tax path`.

<Warning>
  **After the store rejects a request, it returns the same rejection to your next request on the same client.**
  This happens once, on any tax path. After `GET /admin/tax/country-taxes/99999999` returns `404`, your next
  request, such as `GET /admin/tax/country-taxes/4` or `GET /admin/tax/custom-profiles/1`, also returns that
  `404`, even though the record exists. The request after that runs normally, and a request from a new client
  is not affected. A delete sent straight after a `404` returns that `404` and removes nothing. Confirm a delete
  by reading the country tax back with [Retrieve a country tax](/api-reference/country-taxes/retrieve-a-country-tax).
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Wrap every create and update in `country_tax`, and send `country_code` when you create.** A bare
  record, or the plural `country_taxes` key, is rejected with `400` and the message `country_tax missing`.
  A create without `country_code`, or with a code no country has, is rejected with `400 invalid_request`
  and the message `Invalid country_code`. The store fills `country` from `country_code`, and `tax_code`
  too unless you send it, but no response includes `country_code` itself.
- **An update changes only the fields you send.** Fields you leave out keep their values, so you do not
  send `country_code` again. A new `country_code` moves the country tax to that country, and
  `"tax_method": "no_tax"` sets `tax_rate` to `0`.
- **You can file a create under a transaction number.** Send the number in an `X-Transaction-No` header,
  or as `transaction_no` at the top level of the body, beside `country_tax`. The SDKs send it as the header
  when you pass `transaction_no` to the create. A `transaction_no` inside `country_tax` is accepted and
  files nothing. If the header and the body name different numbers, the header wins. No response returns
  the number. `GET /api/v4/admin/transactions/{transaction_no}` then counts the country tax under
  `country_tax`, until you delete it. An update with a number, in the header or beside `country_tax`, files
  the country tax under the new number, and the old number then returns `404`. An update without a number
  leaves the filing as it was.
- **A listing returns up to 100 country taxes per call, newest first.** A larger `limit` is cut to `100`,
  and `pagination.limit` shows `100`. To read every country tax, add `pagination.count` to `offset` after
  each page until `offset` reaches `pagination.total`. `sort` takes `id` or `name`, and sorts in descending
  order either way. `q`, `search`, `country_code`, `is_rest_of_world` and `field_metadata` are accepted and ignored.
- **Read `country.code` to find the country a country tax covers.** On older country taxes, `tax_code` is
  free text such as `GST`, `NO_TAX`, `Tax` or `VAT` rather than the country's code. The store's
  rest-of-the-world country tax has `is_rest_of_world` set to `true` and `country` set to `null`, and its
  state rules have `state` set to `null`. Several country taxes can have `is_default` set to `true` at the
  same time.
- **Row reads and updates return an `ETag`; the store never returns `304`.** Retrieve and update return an
  `ETag` header. Send it as `If-Match` on an update, and the update is rejected with `409` if the country tax
  changed since you read it. The SDK functions send no `If-Match`. `If-None-Match` is ignored: a retrieve
  with the current `ETag` still returns `200` and the full body. The listing and the create return no `ETag`.
- **There is no `HEAD` call for country taxes.** `HEAD` and `OPTIONS` return `404` on the listing and on
  a country tax, whether or not a country tax has that `country_tax_id`. The country tax path also accepts
  `PATCH`, which changes only the fields you send and returns `200` with an `ETag`; the SDKs have no
  function for it. A request the store has no handler for can return `200` with
  `{"isSuccess": false, "message": "Invalid API Request"}` and store nothing, so read the country tax
  back after a write.
