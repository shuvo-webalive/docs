The Shipping classes API has nine endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/shipping_classes`.

<Warning>
  **Updating a shipping class replaces both its `name` and its `description`.** If your `PUT` sends
  only `name`, the store sets the class's `description` to `null`. To keep the description, send it
  again in the same call: `{"shipping_class": {"name": "Bulky Goods", "description": "Items over 20kg"}}`.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Create and update wrap the class in `shipping_class`.** Send
  `{"shipping_class": {"name": "Bulky Goods", "description": "Items over 20kg"}}` to create or
  update a class. A body that sends the fields without the wrapper, or wraps them in the plural
  `shipping_classes` key, is rejected with `400` and the message `shipping_class missing`.
- **`name` and `description` are the only fields you can write.** `name` is required, at most 50
  characters, and must be unique: a name another class already has is rejected with `409`.
  `description` is optional and at most 100 characters. If you leave it out, the store saves
  `null`; an empty string is saved as an empty string. The store ignores an `id`, an `is_default`
  and any unknown field you send inside `shipping_class`.
- **Only one class is the default, and only one call changes it.**
  [Set the default shipping class](/api-reference/shipping-classes/set-the-default-shipping-class) sets `is_default` to `true` on the class
  whose `shipping_class_id` you pass, and to `false` on the class that was the default. You cannot
  delete the default class: make another class the default first, or the delete is rejected with `409`.
- **A listing returns at most 20 classes per call, and the classes you create are listed first.** A
  larger `limit` is capped at `20`, and `pagination.limit` shows `20`. New classes go ahead of the
  classes already there, newest first, so the default class can be past the first page. To get
  more, send the next `page` or a higher `offset` while `pagination.has_next` is `true`.
- **`PATCH` does not change a class.** A `PATCH` on a class returns `200` with
  `{"isSuccess": false, "message": "Invalid API Request"}` and changes nothing. Use `PUT` to
  update a class.
