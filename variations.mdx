The Variations API has sixteen endpoints, and you can call every one from all seven SDKs. Variation type paths start with `/api/v4/admin/variations`, and product variant paths start with `/api/v4/admin/products/{product_id}/variations`.

<Warning>
  **Replacing a variation type deletes every option you leave out of the body.** `PUT` on a type
  keeps only the options you send: an option sent with its `id` is changed, an option sent without
  an `id` is added, and every other option is deleted. To change or add options without deleting any,
  use [Update a variation type](/api-reference/variations/update-a-variation-type), which changes only what you send.
</Warning>

## Before you call

Register your credentials once when your app starts, as shown in
[Authentication (New)](/authentication), or in [Authentication (Legacy)](/authentication-legacy) if your store
signs in with a redirect URI and an auth string. Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Wrap every variation type write in `variation`.** Create, replace and update all take
  `{"variation": {...}}`. A bare record is rejected with `400`: each top-level key is reported with
  the reason `unknown_field`, and `variation` with the reason `required`.
  [Update a product's variants](/api-reference/variations/update-a-products-variants) and [Import a product's variants](/api-reference/variations/import-a-products-variants)
  are the opposite: send their fields at the top level of the body, with no wrapper.
- **Delete a variation type with `cascade=true`.** A type you create always has at least one option,
  and you cannot delete a type's last option on its own. Without `cascade=true`,
  [Delete a variation type](/api-reference/variations/delete-a-variation-type) rejects a type that has options with `409` and the
  message `This variation type still has N option(s).` With `cascade=true`, the type and its options
  are deleted together. A type that a product's variants use cannot be deleted, even with `cascade=true`
  and even after that product is moved to the trash: the call is rejected with `409`.
- **Importing variants can add options to the store's variation types.**
  [Import a product's variants](/api-reference/variations/import-a-products-variants) matches each `product_key` to the `name` of a
  variation type and each variant `key` to that type's option labels. A label the type does not have
  yet is added to the type itself, for the whole store. To add no option, use labels the type already
  has: [List variation types](/api-reference/variations/list-variation-types) returns them.
- **`variation_ids` takes each variant's `variation_id`, not a variation type's `id`.** Each variant that
  [List a product's variants](/api-reference/variations/list-a-products-variants) returns has its own `variation_id`.
  Send those values in `variation_ids` to [Update a product's variants](/api-reference/variations/update-a-products-variants). A variant
  of another product is rejected with `400` and nothing is written.
- **On a product whose prices include tax, the variant prices you read are net of tax.**
  [List a product's variants](/api-reference/variations/list-a-products-variants) returns each variant's `base_price` and
  `sale_price` divided by the tax rate and rounded to the cent: a stored `90.99` reads `82.72`.
  [Update a product's variants](/api-reference/variations/update-a-products-variants) stores the price you send as it is. A price you read
  and write back is therefore not the price that was stored: send the price including tax.
- **A variant's `variation_id` is not its own product `id`.** [Retrieve a product's variant](/api-reference/variations/retrieve-a-products-variant) and [Delete a product's variant](/api-reference/variations/delete-a-products-variant) take the variant's `variation_id`,
  the value [List a product's variants](/api-reference/variations/list-a-products-variants) returns as `variation_id` and `id`. Every variant is also a product row with a third number, its own product `id`, which
  [Check a product SKU](/api-reference/products/check-a-product-sku) reports for the variant's SKU. Retrieving a variant through another product's `product_id` returns `400`. [Retrieve a product's variant](/api-reference/variations/retrieve-a-products-variant)
  names the availability `active` where the list names it `available`. Deleting a variant is permanent: it returns `204`, and deleting it again returns `404`.
- **The listing returns 20 types per call unless you send `limit`.** `limit` takes `1` to `100`. To get
  more, send a higher `offset`, or the next `page`, while `pagination.has_next` is `true`. The listing
  accepts only `search`, `standard`, `limit`, `offset`, `page` and `field_metadata`: any other query
  parameter, such as `q` or `sort`, is rejected with `400` and the reason `unknown_parameter`.
- **Update one variant with a bare body, and read the result back from the variant.** [Update a product's variant](/api-reference/variations/update-a-products-variant) takes `available`, `name`, `sku`, `custom_sku`, `barcode`, `country_of_origin`, `hs_code`, `pricing`, `inventory` and `ordering`
  at the top level of the body, with no wrapper, and changes only the fields you send. It returns the variant's ids and codes, not its pricing or stock: read the rest with [Retrieve a product's variant](/api-reference/variations/retrieve-a-products-variant), which names `available` as `active`.
  A key the call does not know, `active`, a `variation` wrapper and a body `id` are ignored and the call still returns `200`. A SKU another variant holds is rejected with `409`.
- **Delete every variant of a product in one call.** [Delete all of a product's variants](/api-reference/variations/delete-all-of-a-products-variants) returns `204` with no body, also when the product has no variants. [List a product's variants](/api-reference/variations/list-a-products-variants) then returns `{"variations": []}`.
  To delete one variant, use [Delete a product's variant](/api-reference/variations/delete-a-products-variant).
