The Category page API has five endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/settings/page_settings/category_page`.

<Warning>
  Every write body must be wrapped in a key, and the key depends on the path. On `/category_page`,
  wrap the fields in `category_page` and then in the section name. On `/category_page/{section}`,
  wrap them in the section's own name only, such as `category_information`: a body wrapped in
  `category_page`, or not wrapped at all, is rejected with `400 invalid_request`.
</Warning>

## Before you call

Set up a client once with your store's credentials, as shown in [Authentication](/authentication).
The SDK samples on these pages use that client. With cURL, send the access token in an
`Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **The settings are split into two sections.** `category_information` controls the category itself
  and its subcategory list. `product_information` controls each product card and how the product
  listing displays, pages and sorts. Read or write both through `/category_page`, or one through
  `/category_page/{section}`. An unknown section returns `404 not_found`.
- **`PATCH` is the only way to write, and it changes only the fields you send.** Fields you leave out
  keep their stored values, including other fields in the same nested block and a section you did
  not name. `PUT`, `POST` and `DELETE` are rejected on both paths with `405 method_not_allowed`
  and an `Allow: GET, HEAD, PATCH, OPTIONS` header.
- **Add `field_metadata=true` to a read to get a description of every field.** The settings are
  still returned with it. Each entry gives the field's `ui_label`, `description`, `type` and
  `default`, and every `enum` field also lists its `allowed_values`, with a label for each in
  `labels`. For `variation_combination.types`, `allowed_values` lists the variation types your store
  defines, with the ids you can send. On `/category_page` the block is keyed by section; on a
  section it is keyed by field name.
- **All category page writes share one rate limit.** If you send eleven writes within about 2.3
  seconds, the eleventh is rejected with `429` and a `Retry-After` header that counts down the time
  left before writes are accepted again. Until then, writes to either section and to
  `/category_page` are all rejected, while reads still return `200`. A retry before then counts as
  another write, so wait until `Retry-After` has passed before you write again.
- **`400`, `404` and `405` responses share one shape:** an `error` object with `code`, `message`,
  `details` (one entry per rejected field, each with its own `field`, `code` and `message`) and
  `request_id`.
