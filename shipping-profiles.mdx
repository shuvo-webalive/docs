The Shipping profiles API has eleven endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/shipping_profiles`.

<Warning>
  **Sending `default` as `true` changes the default shipping profile for the whole store.**
  [Create a shipping profile](/api-reference/shipping-profiles/create-a-shipping-profile) or
  [Update a shipping profile](/api-reference/shipping-profiles/update-a-shipping-profile) with `default` set to `true` makes that profile the
  default and sets `default` to `false` on the profile that was the default. Before you call either, find
  the current default, the profile in [List shipping profiles](/api-reference/shipping-profiles/list-shipping-profiles) with `default=true`, so
  you can set it back. You cannot set `default` to `false` on the default profile, and you cannot delete
  it: both are rejected with `409`. Make another profile the default first.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Create, replace, update and the wizard wrap the profile in `shipping_profile`.** Send
  `{"shipping_profile": {...}}`. A body without the wrapper is rejected with `400`. A field the profile
  does not have is rejected with `400`, and so is an `id` in the body. Responses return the profile inside
  `shipping_profile`.
- **`rule_preference` decides which rule applies when several match.** It is `product_assigned_rule`, the
  default, `lowest_shipping_cost_rule` or `highest_shipping_cost_rule`. The short codes `hp`, `lsc` and
  `hsc` are accepted on a write, and the profile returns the long names. Any other value is rejected
  with `400`.
- **`shipping_rules` is the whole list of rule `id` values, and each rule appears once.** Send the `id` of
  each shipping rule. An unknown `id` or a repeated one is rejected with `400`. An update with
  `"shipping_rules": []` takes every rule off the profile, and the rules stay in the store. A profile
  returns each rule with its `id`, its `name` and its shipping rate, or `null` when the rule has none.
- **`PUT` replaces a profile, and `PATCH` changes only the fields you send.**
  [Replace a shipping profile](/api-reference/shipping-profiles/replace-a-shipping-profile) needs `name`, `description`, `rule_preference` and
  `shipping_rules`, and names each missing field in the `400` response with the reason `required`.
  `description` takes `null`. To change one field, use [Update a shipping profile](/api-reference/shipping-profiles/update-a-shipping-profile).
- **The wizard creates a profile, its rules and their rates in one call.** [Create a shipping profile with the
  wizard](/api-reference/shipping-profiles/create-a-shipping-profile-with-the-wizard) returns `201` for a new profile `name`. When a profile already has that
  `name`, it adds the new rules to that profile and returns `200`. Any bad value saves nothing. Only a
  `POST` works on the wizard path: a `GET` or `HEAD` is rejected with `405`.
- **A listing returns 20 profiles per call unless you send `limit`, and the newest profile comes first.**
  `limit` takes `1` to `100`, and `offset` skips profiles. To get more, send a higher `offset` while
  `pagination.has_next` is `true`. A query parameter the listing does not know is ignored.
