The Pages API has fifteen endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/pages`.

<Warning>
  **[Set the landing page](/api-reference/pages/set-the-landing-page) changes the landing page for the whole store.**
  The page you name gets `landing` `true`, and the page that was the landing page gets `false`.
  Before you call it, find the current landing page, the row with `landing` `true` in
  [List pages](/api-reference/pages/list-pages) with `limit=all`, so you can set it back. The landing page cannot be
  deleted. [Delete a page](/api-reference/pages/delete-a-page) without `force=true` moves the page to the trash, and
  with `force=true` deletes it permanently.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Wrap the fields of every write in `page`, except when you change a URL.** Create, replace and update
  take `{"page": {...}}`, and a bare record is rejected with `400` and the reason `unknown_field`.
  [Change the URL of a page](/api-reference/pages/change-the-url-of-a-page) is the exception: it takes a bare `{"url": "..."}`, and a
  body wrapped in `page` is rejected with `400`. Responses return the page inside `page`.
- **`PUT` replaces a page, and `PATCH` changes only the fields you send.**
  [Replace a page](/api-reference/pages/replace-a-page) needs ten fields: `name`, `title`, `subtitle`, `url`, `layout`,
  `visibility`, `body_class`, `active`, `disable_tracking` and `password_protection`. Each one you leave
  out is named in the `400` response with the code `required`. To change one field, use
  [Update a page](/api-reference/pages/update-a-page).
- **A deleted page stays in the trash until you delete it with `force=true`.** A page in the trash is left
  out of [List pages](/api-reference/pages/list-pages), but [Retrieve a page](/api-reference/pages/retrieve-a-page) still returns it
  with `in_trash` set to `true`. [Update a page](/api-reference/pages/update-a-page) on it is rejected with `409`, and a
  second delete without `force=true` with `400`. A page in the trash is listed in
  [List items in the trash](/api-reference/trash/list-items-in-the-trash) until you delete it permanently.
- **Send `If-Match` to avoid overwriting someone else's change.** [Retrieve a page](/api-reference/pages/retrieve-a-page),
  replace, update, the URL change, setting the landing page and duplicating all return the page's
  `ETag` header; creating a page does not. Send that value, quotes included, as `If-Match` on a replace,
  update or delete. If the page changed since, the call is rejected with `412` and the reason
  `precondition_failed`, before the body is checked.
- **A listing returns 20 pages per call unless you send `limit`.** `limit` takes `1` to `100`, or `all`
  for every page in one call; with `all`, `pagination.limit` is the total. To get more, send a higher
  `offset` while `pagination.has_next` is `true`. A query parameter the listing does not accept, or
  one you send twice, is rejected with `400`.
- **`visibility` is `open`, `hidden` or `restricted`, but some older pages return other values.** A page
  can return a `visibility` such as `OPEN` or `public`, as it was stored. Treat any value other than the
  three as unknown. The `visibility` filter on the listing matches in any letter case, so
  `visibility=open` also returns pages stored as `OPEN`.
