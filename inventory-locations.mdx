The Inventory locations API has ten endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/inventory_locations`.

<Warning>
  **Replacing a location resets every field you leave out of the body.** `PUT` on a location does
  not merge: `address` becomes `""`, and `is_active` and `is_default` become `false`. If you
  replace the default location and leave out `is_default`, the store has no default location
  until you give the flag back with [Set the default inventory location](/api-reference/inventory-locations/set-the-default-inventory-location).
  Send every field you want to keep, `is_default` included.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Send the fields at the top level of the body, not inside `inventory_location`.** Create and
  replace both read `name`, `address`, `is_active` and `is_default` from the top level. A create
  wrapped in `{"inventory_location": {...}}` is rejected with `400` and the message
  `name is required`. Responses return the location inside `inventory_location`.
- **At most one location is the default.**
  [Set the default inventory location](/api-reference/inventory-locations/set-the-default-inventory-location) gives the flag to the location you name and
  takes it from the location that had it. A create with `"is_default": true` takes the flag the same
  way, and a replace that leaves out `is_default` clears it. You cannot delete the default location:
  make another location the default first, or the delete is rejected with `409`.
- **A listing returns at most 20 locations per call, whatever `limit` you send.** The store checks
  `limit` but does not apply it: `pagination.limit` always shows `20`, and `limit=0` is rejected
  with `400`. To get more, send a higher `offset`, or a `page` (read as `offset = (page - 1) * 20`),
  while `pagination.has_next` is `true`. The stock listing pages the same way, 20 products at a
  time. Unknown query parameters are ignored, not rejected.
- **A `200` does not prove a write worked.** For a method these paths do not support, such as
  `PATCH` on a location or any write to `/stock`, the store returns `200` with
  `{"isSuccess": false, "message": "Invalid API Request"}` and stores nothing. Use `PUT` to
  replace a location, and [Activate or deactivate an inventory location](/api-reference/inventory-locations/activate-or-deactivate-an-inventory-location) to change
  only `is_active`. No call changes stock.
