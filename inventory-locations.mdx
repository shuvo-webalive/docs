The Inventory locations API has ten endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/inventory_locations`.

<Warning>
  **Replacing a location resets `address` and `active` when you leave them out of the body.** `PUT`
  on a location does not merge: `address` becomes `null` and `active` becomes `true`. A `default`
  you leave out keeps its value. Send every field you want to keep.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Send the fields at the top level of the body, not inside `inventory_location`.** Create and
  replace both accept only `name`, `address`, `active` and `default`, at the top level. Any other
  field, including a wrapping `inventory_location`, is rejected with `400`. Responses return the
  location inside `inventory_location`.
- **`is_active` and `is_default` are still accepted in request bodies.** The store reads them as
  `active` and `default` and returns only the new names. If you send both spellings of a field with
  different values, the request is rejected with `400` and the reason `conflicting_field`.
- **At most one location is the default.**
  [Set the default inventory location](/api-reference/inventory-locations/set-the-default-inventory-location) gives the flag to the location you name and
  takes it from the location that had it. A create or replace with `"default": true` takes the flag
  the same way. You cannot take the flag away with `"default": false` or delete the default
  location: make another location the default first, or the request is rejected with `409`.
- **A listing returns 20 locations per call unless you send `limit`.** `limit` takes `1` to `100`,
  and `pagination.limit` shows the page size applied. To get more, send a higher `offset` while
  `pagination.has_next` is `true`. The listing accepts only `q`, `limit` and `offset`, and the stock
  listing only `limit` and `offset`: any other query parameter, `page` included, is rejected with
  `400`.
- **A `200` does not prove a write worked.** For a method these paths do not support, such as
  `PATCH` on a location or any write to `/stock`, the store returns `200` with
  `{"isSuccess": false, "message": "Invalid API Request"}` and stores nothing. Use `PUT` to
  replace a location, and [Activate or deactivate an inventory location](/api-reference/inventory-locations/activate-or-deactivate-an-inventory-location) to change
  only `active`. No call changes stock.
