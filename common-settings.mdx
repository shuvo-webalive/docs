The Common settings API has six endpoints, and you can call every one from all seven SDKs. The paths start with `/api/v4/settings` and `/api/v4/create-customer-fields`, directly under `/api/v4` and not under `/api/v4/admin`.

<Warning>
  **A write changes settings for the whole store and returns every settings group.** Only the keys you
  send change, but one entry that is not valid rejects the whole request with `400` and nothing is saved.
  The response is about 2 MB, and a write can take from 5 to more than 50 seconds, longer than the
  SDKs' default timeout of 30 seconds: build the client with a longer timeout, such as 120 seconds.
  Never send a `***` value back: it is the mask a read returns for a secret, not the stored value.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Send `type` on every read.** Without it, [Get settings](/api-reference/common-settings/get-settings) returns every group,
  about 2 MB, and can take 30 seconds or more. `type` names one group, such as `general`, `locale`,
  `email`, `e_commerce` or `customer_registration_field`. An unknown group, or a comma list of groups
  such as `general,locale`, is rejected with `404`.
- **Read one key per call with `config_key`.** A comma list such as `abn_label,abn_placeholder` matches
  nothing and returns `{"settings": {}}` with `200`. Send one call per key, or read the whole group
  with `type` alone.
- **Every value is text, except in the `notifications` group.** Values come back as strings, such as
  `"true"` or `"18"`, and a number you write is stored as its text: `5` becomes `"5"`. The
  `notifications` group is an object of names to `true` or `false`, such as
  `{"order_emails_enabled": true, "customer_emails_enabled": true}`, not a list.
- **Passwords, keys and tokens read as `***`.** This includes `smtp_password` in the `email` group and
  the `password_*` and `retype_password_*` keys in `customer_registration_field`. Write only the keys
  you change, so you never send a `***` value back.
- **The registration form returns booleans where the settings read returns text.**
  [Get the customer registration fields](/api-reference/common-settings/get-the-customer-registration-fields) returns each field's `_active` and
  `_required` as `true` or `false`. Reading the same keys from the `customer_registration_field` group
  returns them as text, such as `"true"`. `_order` is text in both.
- **`/settings` accepts `GET`, `HEAD`, `PUT` and `POST`; `/create-customer-fields` accepts only `GET` and `HEAD`.**
  An `OPTIONS` request returns these methods in its `Allow` header. Neither path sends an `ETag`
  header.
