The Products API has nine endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/products`.

<Warning>
  **Setting a product's stock unassigns every location you leave out, even one that still holds stock.**
  [Set a product's stock](/api-reference/products/set-a-products-stock) replaces the product's whole set of locations with the
  rows you send in `locations`. Read the rows first with [Retrieve a product's stock](/api-reference/products/retrieve-a-products-stock),
  send every row you want to keep, and change only the values you mean to change.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Send product fields at the top level of the body, not inside `product`.** Responses return the
  product inside `product`, but a create or `PUT` body wrapped in `product` is rejected with `400` and
  the message `product: is not a recognised product field`. A `PATCH` body wrapped in `product` is
  rejected with `400` in a different error shape, with `code` set to `validation_error` and the rejected
  fields in `errors`. Send the stock body's `note` and `locations` at the top level too.
  [Import a product's reviews](/api-reference/products/import-a-products-reviews) is the exception: wrap its reviews in `product`.
- **`PUT` and `PATCH` both change only the fields you send, at every level.** `{"advanced": {"advance_information": {"mpn": "MPN-0001"}}}`
  changes `mpn` and keeps the other eight fields of `advance_information`. A body that changes nothing,
  `{}` included, returns `200` and leaves `version` and the `ETag` header as they were.
- **Deleting a product moves it to the trash.** [Delete a product](/api-reference/products/delete-a-product) returns `204`, but
  [Retrieve a product](/api-reference/products/retrieve-a-product) still returns the product, with `status` set to `trashed`.
  Every write to a product in the trash, including `PUT`, `PATCH` and importing reviews, is rejected with
  `409`, and deleting it again returns `404` with the message `Product already in trash`.
- **Tag a create with a transaction number in the `X-Transaction-No` header or the body.** [Create a product](/api-reference/products/create-a-product),
  [Import a product's reviews](/api-reference/products/import-a-products-reviews) and [Import a product's variants](/api-reference/variations/import-a-products-variants)
  take an optional `X-Transaction-No` header; in the SDKs, pass `transaction_no`. You can send
  `transaction_no` in the body instead. When you send both with different values, the header's value is
  stored and the body's is lost, with no error. On `PUT` and `PATCH` the header is ignored, and a body
  `transaction_no` is stored only on a product that has none: a product that has one keeps it.
- **Some fields you read cannot be written.** A changed `id`, `created_at`, `created_on`, `custom_class`,
  `sold_out`, `sold_out_label`, `length`, `width`, `height`, `weight`, `featured`, `new`, `model`, `is_draft`,
  `has_variations`, `urls` or `created_by` is rejected with `400` and the reason `read_only_field`; the value
  you read is accepted. `status` and `reviews` are rejected with the reason `unknown_field`, so remove them
  before you send back a product you read. Write the dimensions in `product_properties`, and `mpn`, `upc`,
  `barcode` and `hs_code` in `advanced.advance_information`. `field_metadata` lists these fields as writable
  at the top level, but they are rejected there.
- **Setting stock changes the product too.** `available_stock` is the sum of the rows' `stock`, and
  `product_pricing_and_stock.low_level_stock` takes the `low_stock_level` of the product's default
  location. The product's `version`, `updated_at` and `last_updated_by` change when the stock changes.
  `product_pricing_and_stock.locations` on [Retrieve a product](/api-reference/products/retrieve-a-product) holds the same rows as
  [Retrieve a product's stock](/api-reference/products/retrieve-a-products-stock).
- **The first location you assign to a product is missing from the response.** On a product with no
  location yet, [Set a product's stock](/api-reference/products/set-a-products-stock) returns `locations: []` and stores the row.
  Call [Retrieve a product's stock](/api-reference/products/retrieve-a-products-stock) to see it. A product that already has a location
  returns its rows at once.
- **Find a `product_id` in a create response or an inventory location's stock.** None of these nine
  endpoints lists products. [Create a product](/api-reference/products/create-a-product) returns the new product's `id` as
  `product.id`. For a product that already exists, [List stock at an inventory location](/api-reference/inventory-locations/list-stock-at-an-inventory-location)
  returns the `id` of each product the location holds, as `items[].product.id`.
