The Orders API has 24 endpoints, and you can call every one from all seven SDKs. Most paths start with `/api/v4/admin/orders`; [Refund a payment](/api-reference/orders/refund-a-payment) uses `/api/v4/admin/payment`, [Add a custom order status](/api-reference/orders/add-a-custom-order-status) uses `/api/v4/admin/order`, and [List a customer's orders](/api-reference/orders/list-a-customers-orders) uses `/api/v4/admin/customers`.

<Warning>
  **Two paths take the order's `internal_id`, not its `order_id`.**
  [Retrieve an order's custom fields](/api-reference/orders/retrieve-an-orders-custom-fields) and [Send an order's invoice](/api-reference/orders/send-an-orders-invoice)
  find the order by its `internal_id`. If you pass an `order_id`, they return `404`, or, when another order
  has that number as its `internal_id`, they return that order's custom fields or email that order's invoice.
  Every other order path takes the `order_id`. Responses that return an order include both numbers.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **An order comes back in one of two shapes.** [Retrieve an order](/api-reference/orders/retrieve-an-order),
  [List orders](/api-reference/orders/list-orders), [Update an order](/api-reference/orders/update-an-order) and
  [Update selected order fields](/api-reference/orders/update-selected-order-fields) return it in sections: `customer`, `billing_address`,
  `shipping_address`, `items`, `shipping`, `discounts`, `charges_totals`, `payments` and `fulfillment`.
  The two create calls, [Cancel an order](/api-reference/orders/cancel-an-order), [Change an order's status](/api-reference/orders/change-an-orders-status) and
  [List a customer's orders](/api-reference/orders/list-a-customers-orders) return it flat: the totals and fulfillment fields at the
  top level, the customer in `customer_summary` and the lines in `order_line_details`. A listing row has no
  `billing_address` or `shipping_address`.
- **The customer filters take different customer numbers.** The `customerId` filter of
  [List orders](/api-reference/orders/list-orders) and [Count orders](/api-reference/orders/count-orders) takes the customer's `internal_id`, and the
  customer's `customer_id` matches nothing there. [List a customer's orders](/api-reference/orders/list-a-customers-orders) takes the
  `customer_id`, and the customer's `internal_id` returns `404` there.
- **Every address you send replaces the whole stored address.** This holds when you create an order and in
  [Update an order](/api-reference/orders/update-an-order), [Update selected order fields](/api-reference/orders/update-selected-order-fields) and
  [Update an order's addresses](/api-reference/orders/update-an-orders-addresses): a field you leave out becomes `""`. `company_name` is
  never stored and always reads `""`. An address without `first_name` returns `500` with the body `{}`, and on
  an update an address without `country_code` returns `500` with the message
  `Cannot get property 'id' on null object`. Send both in every address.
- **A listing returns at most 20 orders per call and leaves out cancelled orders.** A larger `limit` is capped
  at `20`, and `pagination.limit` shows `20`. Send `page` or `offset` for the next orders; when you send both,
  `offset` wins. Cancelled orders are listed only when you send `order_status=cancelled`, and
  [Count orders](/api-reference/orders/count-orders) leaves them out too. A query parameter that is not on the
  [List orders](/api-reference/orders/list-orders) page, `q` included, is rejected with `400`.
- **Payments and refunds change different totals.** [Record a payment on an order](/api-reference/orders/record-a-payment-on-an-order) raises
  `paid`. [Refund a payment](/api-reference/orders/refund-a-payment) lowers `paid` and raises `refunded`, and needs an
  `Idempotency-Key` header. [Refund an order](/api-reference/orders/refund-an-order) raises `refunded` and leaves `paid` as it was.
- **Shipping lowers stock, and deleting the order does not restore it.** [Create a shipment](/api-reference/orders/create-a-shipment)
  lowers the stock of a product that tracks its stock by the units shipped. Creating, paying, cancelling,
  completing and deleting an order change no stock.
