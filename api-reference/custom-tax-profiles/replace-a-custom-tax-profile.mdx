---
title: "Replace a custom tax profile"
description: "Replaces a profile's `description` and `tax_code`, setting any you leave out to `null`, changes `name` only when you send it, and returns the profile."
openapi: "PUT /admin/tax/custom-profiles/{custom_profile_id}"
---

Replaces the profile whose `id` you pass as `custom_profile_id`, and returns it under `custom_profile` with the eight fields of a listing row and an `ETag` header. Wrap the record in `custom_profile`. A `description` or `tax_code` you leave out comes back `null`, so send the current values to keep them. A `name` you leave out keeps its value, and an empty `name` is rejected with `400`. Send an `If-Match` header with the `ETag` from your last read if you want the update rejected with `409` when the profile changed since then. A `transaction_no` at the top level of the body, or in an `X-Transaction-No` header, files only a profile that has no number yet.

<Note>The SDK samples get their client from credentials your app registers once when it starts, as shown in [Authentication (New)](/authentication#set-up-a-client). To try the call here, click **Try it**, set `store` to your store's host name and paste an access token. Get the token as shown in [Authentication (New)](/authentication#calling-the-api-directly), or in [Authentication (Legacy)](/authentication-legacy#calling-the-api-directly) if your store signs in with a redirect URI and an auth string. To send a raw JSON body instead of filling in fields, copy the cURL sample and edit its `-d` payload.</Note>
