---
title: "Restore items in bulk"
description: "Restores up to 100 trashed items and returns the restored items and the items that failed."
openapi: "POST /admin/trash/bulk-restore"
---

Send `items`, a list of 1 to 100 objects, each with the item's `type` and `id`, at the top level of the body. You get `200` when every item is restored, and `207` with the same body when any item fails, even if none is restored, so check `failed` in every response. `restored` lists each restored item as [Restore an item from the trash](/api-reference/trash/restore-an-item-from-the-trash) returns it, and `failed` lists each failed item with its `type`, `id`, `code` and `message`. The `code` is `not_in_trash` for an item that is not in the trash and `not_found` for an id the type does not have. An item listed twice is restored once and reported once.

<Note>The SDK samples get their client from credentials your app registers once when it starts, as shown in [Authentication](/authentication#set-up-a-client). To try the call here, click **Try it**, set `store` to your store's host name and paste an access token from [Get an access token](/api-reference/authentication/get-an-access-token). To send a raw JSON body instead of filling in fields, copy the cURL sample and edit its `-d` payload.</Note>
