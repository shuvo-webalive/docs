---
title: "Count products"
description: "Returns how many products match the filters you send, without the products themselves."
openapi: "GET /admin/products/count"
---

Returns `total` and `count`, which hold the same number: the products that match the filters. Draft products are counted and products in the trash are not, so with no filter the count equals `pagination.total` of [List products](/api-reference/products/list-products). Send the list's filters: `search_text`, `name`, `sku`, `ids`, `parent`, `product_type`, `status`, `stock`, `is_available`, `is_inventory_enabled`, `created_by`, `price_from`, `price_to`, `created_from`, `created_to`, `updated_from` and `updated_to`. `productType` and `priceFrom` work as well as `product_type` and `price_from`, and the error messages name the camelCase form. Paging and sorting parameters, such as `limit`, `offset` and `sortBy`, are rejected with `400` and the reason `unknown_parameter`. `HEAD` on this path returns `404`.

<Note>The SDK samples get their client from credentials your app registers once when it starts, as shown in [Authentication (New)](/authentication#set-up-a-client). To try the call here, click **Try it**, set `store` to your store's host name and paste an access token from [Get an access token (New)](/api-reference/authentication/get-an-access-token-new), or from [Get an access token (Legacy)](/api-reference/authentication/get-an-access-token) if your store signs in with a redirect URI and an auth string.</Note>
