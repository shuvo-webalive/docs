---
title: "Update a product's variant"
description: "Changes the fields you send on one variant of the product and returns the variant's ids and codes."
openapi: "PATCH /admin/products/{product_id}/variations/{variation_id}"
---

Send any of `available`, `name`, `sku`, `custom_sku`, `barcode`, `country_of_origin`, `hs_code`, `pricing`, `inventory` and `ordering` at the top level of the body, with no wrapper. Only the fields you send change. The call returns `status`, `message` and the `variation` with its `variation_id`, `name`, `sku`, `custom_sku`, `barcode`, `country_of_origin` and `hs_code`. It does not return the pricing or stock: read them with [Retrieve a product's variant](/api-reference/variations/retrieve-a-products-variant), where `available: false` reads as `active: false`. A key the call does not know, `active`, a `variation` wrapper and a body `id` are ignored, and the call still returns `200`. `available` is not checked for type. To change several variants at once, use [Update a product's variants](/api-reference/variations/update-a-products-variants).

<Note>The SDK samples get their client from credentials your app registers once when it starts, as shown in [Authentication](/authentication#set-up-a-client). To try the call here, click **Try it**, set `store` to your store's host name and paste an access token from [Get an access token](/api-reference/authentication/get-an-access-token). To send a raw JSON body instead of filling in fields, copy the cURL sample and edit its `-d` payload.</Note>
