---
title: "Create an order"
description: "Creates an order for the products you send and returns it with its `order_id`."
openapi: "POST /admin/orders"
---

Send the fields at the top level of the body, not wrapped in `order`; only `products` is required, each line with a `product_id` and a `quantity`. Without `customer_id` the order is a guest order; `payment_gateway` defaults to `PIS` (pay in store), and `delivery_type` defaults to `shipping`. The new order is `in_progress` and `unpaid`, and with `PIS` its `payments` holds one `awaiting` payment for the grand total. A `transaction_no` another order already has creates a second order: the store does not check it for duplicates. To file the order under a transaction number, send the `X-Transaction-No` header or `transaction_no` in the body; when the two differ, the header wins.

Whether creating the order lowers stock depends on the store. When an order lowers stock depends on the store's `update_stock` setting, which [Get a settings section](/api-reference/ecommerce-settings/get-a-settings-section) returns for the `product_inventory` section: `after_order` lowers stock when the order is created, `after_payment` when it is paid, and `after_shipment` when you [create a shipment](/api-reference/orders/create-a-shipment). Read it before you sync stock, so you do not take the same units off twice. Some stores also require `billing_address`: such a store refuses an order without one with `400` and the message `billing.address.required`, so send `billing_address` whenever you have it. **A new store ships nothing until it has a default shipping profile.** Without one, every order with `delivery_type` `shipping` or `delivery` is refused with `400` and the message `We do not ship to your location. Please choose a different shipping address.` Create a profile with [Create a shipping profile with the wizard](/api-reference/shipping-profiles/create-a-shipping-profile-with-the-wizard), then set it as `default_shipping_profile` with [Update shipping settings](/api-reference/shipping-settings/update-shipping-settings): creating the profile alone is not enough. `store_pickup` and `others_shipping` orders need no profile. See [Prepare a new store](/prepare-a-new-store).

<Note>The SDK samples get their client from credentials your app registers once when it starts, as shown in [Authentication (New)](/authentication#set-up-a-client). To try the call here, click **Try it**, set `store` to your store's host name and paste an access token. Get the token as shown in [Authentication (New)](/authentication#calling-the-api-directly), or in [Authentication (Legacy)](/authentication-legacy#calling-the-api-directly) if your store signs in with a redirect URI and an auth string. To send a raw JSON body instead of filling in fields, copy the cURL sample and edit its `-d` payload.</Note>
