The Custom tax profiles API has five endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/tax/custom-profiles`, with a hyphen, and these profiles are separate from the tax profiles at `/api/v4/admin/tax_profiles`. The old path `/api/v4/admin/tax/custom_profiles`, with an underscore, returns `404` with the message `Unknown tax path`.

<Warning>
  **After the store rejects a request, it returns the same rejection to your next request on the same client.**
  This happens once, on any tax path. After `GET /admin/tax/custom-profiles/99999999` returns `404`, your next
  `GET /admin/tax/custom-profiles/1` also returns `404` with the message `Profile not found`, even though that
  profile exists. The request after that runs normally, and a request from a new client is not affected. A
  delete sent straight after a `404` returns that `404` and deletes nothing. So after a rejected call, send one
  read, such as [List custom tax profiles](/api-reference/custom-tax-profiles/list-custom-tax-profiles) with `limit=1`, and ignore its response before
  your next write. To confirm a write, read the profile back.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **Every write wraps the profile in `custom_profile`.** Send
  `{"custom_profile": {"name": "Wholesale customers", "description": "Rates for wholesale accounts"}}` to create
  or replace a profile. A bare record, or the plural `custom_profiles` key, is rejected with `400` and the message
  `custom_profile missing`.
- **An update replaces `description` and `tax_code`, so send them every time.** A `description` or `tax_code` you
  leave out comes back `null`, so send the current values again to keep them. A `name` you leave out keeps its
  value, and an empty `name` is rejected with `400` and the message `Profile name is required`. The updates for
  tax profiles, tax rules and country taxes change only the fields you send; this one does not.
- **Write `tax_code`, not `code`.** The create accepts a `code` and discards it, so `tax_code` stays `null`.
  Send `tax_code` to set the profile's tax code.
- **You can file a create under a transaction number.** Send the number in an `X-Transaction-No` header, or as
  `transaction_no` at the top level of the body, beside `custom_profile`. The SDKs send it as the header when you
  pass `transaction_no` to the create. A `transaction_no` inside `custom_profile` is accepted and files nothing.
  If the header and the body name different numbers, the header wins. No response returns the number.
  `GET /api/v4/admin/transactions/{transaction_no}` then counts the profile under `custom_tax_profile`. A profile
  keeps the first number it is filed under: an update with a number files only a profile that has none yet.
- **A listing returns up to 100 profiles per call, newest first.** A larger `limit` is cut to `100`, and
  `pagination.limit` shows `100`. To read every profile, add `pagination.count` to `offset` after each page
  until `offset` reaches `pagination.total`. `sort` takes `id` or `name`, and sorts in descending order either way.
  `q`, `search` and `field_metadata` are accepted and ignored.
- **Row reads and updates return an `ETag`; the store never returns `304`.** Retrieve and update return an `ETag`
  header. Send it as `If-Match` on an update, and the update is rejected with `409` if the profile changed since
  you read it. The SDK functions send no `If-Match`. `If-None-Match` is ignored: a retrieve with the current
  `ETag` still returns `200` and the full body. The listing and the create return no `ETag`.
- **There is no `HEAD` call for custom tax profiles.** `HEAD` and `OPTIONS` return `404` on the listing and on a
  profile, whether or not a profile has that `custom_profile_id`. The profile path also accepts `PATCH`, which
  changes only the fields you send and returns `200` with an `ETag`; the SDKs have no function for it. A request
  the store has no handler for can return `200` with `{"isSuccess": false, "message": "Invalid API Request"}`
  and store nothing, so read the profile back to confirm a change.
