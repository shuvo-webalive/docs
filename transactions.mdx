The Transactions API has six endpoints, and you can call every one from all seven SDKs. Every path starts with `/api/v4/admin/transactions`.

<Warning>
  **Do not follow `url` or `items_url` for a number that contains a space or a `/`.** The store
  writes a space in these links as `+` and then reads a `+` in a path as a literal `+`, so the link
  returns `404`. Pass `transaction_no` to the SDK function instead: the SDKs percent-encode it, so a
  space reaches the store intact. A number that contains `/` cannot be read at all: the request is
  rejected with `400` and an HTML page, `Invalid URI: [The encoded slash character is not allowed]`,
  before it reaches the API. Do not use `/` in the transaction numbers you send.
</Warning>

## Before you call

Register your store's credentials once when your app starts, as shown in
[Authentication](/authentication). Every SDK sample on these pages then gets its client in one line.
With cURL, send the access token in an `Authorization` header: `Authorization: Bearer $ACCESS_TOKEN`.

## Things to know

- **You can only read transaction numbers.** A create call that sends a `transaction_no` stamps that
  number on the record it creates, and this API reads the numbers back. Every path accepts `GET`,
  `HEAD` and `OPTIONS`, and `OPTIONS` returns `204` with `Allow: GET, HEAD, OPTIONS`. `POST`, `PUT`,
  `PATCH` and `DELETE` are rejected with `405 method_not_allowed` and the message
  `HTTP method not allowed for this endpoint.`
- **A record you delete stays counted.** After you delete a category stamped with a number, using
  [Delete a category](/api-reference/categories/delete-a-category), the number's `total_records`, its `category`
  count and the category's row under `items` do not change. The number also stays in the listing.
- **`transaction_no` matches exactly, letter case included.** The number in lower case returns
  `404` when it was stored in upper case. The store trims surrounding spaces off a number when it
  stores one, so send the number without them.
- **The two listings handle a large `limit` differently.** [List transactions](/api-reference/transactions/list-transactions)
  holds a `limit` above `200` to `200` and shows `200` in `pagination.limit`.
  [List the records of a transaction](/api-reference/transactions/list-the-records-of-a-transaction) rejects it with `400` and the message
  `max cannot exceed 200`. Both default to `20` and accept `max` as another name for `limit`.
- **`pagination` has ten keys.** `total`, `limit`, `offset`, `count`, `current_page`, `total_pages`,
  `has_next`, `has_previous`, `previous_page` and `next_page`; the last two are absolute URLs or
  `null`. Past the last row, both listings return no rows, `has_previous` set to `false` and
  `current_page` equal to `total_pages`. No response here has an `ETag` header, and every one has
  `Cache-Control: no-cache, no-store`.
- **Errors have one shape.** The body is an `error` object with `code`, `message`, `details` and
  `request_id`. A rejected query parameter adds one `details` entry with its `field`, `code`,
  `message` and the `value` you sent; `message` can be `null`. On
  [List transactions](/api-reference/transactions/list-transactions), a rejected `limit` returns two entries, one for `limit`
  and one for `max`. `details` is empty on a `405` and on an unknown path below `/transactions`,
  which returns `404` with the message `No such endpoint: GET <path>`.
